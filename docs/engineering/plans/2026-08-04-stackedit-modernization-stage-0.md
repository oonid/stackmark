# StackEdit Modernization Stage 0 Implementation Plan

> **How to work this plan:** implement it task by task, in order, and complete a task's prescribed checks before starting the next. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove on KDE neon 24.04 that the clean StackEdit rewrite can use a Docker-only JavaScript toolchain, share a Vue/Vite frontend with Tauri, safely render KaTeX and isolated Mermaid SVG, paginate and print through WebKitGTK, detect external file changes, atomically save Markdown, and produce an installable `.deb`.

**Architecture:** This is a vertical feasibility slice, not the full phase-one product. A small Vue app exercises framework-independent render and platform interfaces; a narrow Tauri shell supplies folder selection, scoped atomic writes, and native watching. JavaScript commands enter through `./dev` and run in Docker, except that host-native `cargo tauri dev` owns the interactive WebKitGTK window. Stage 1 is planned only after every mandatory gate has evidence or an approved fallback.

**Tech Stack:** Node 24.18.0 LTS, pnpm 11.20.0, Vue 3.5.40, Vite 8.1.5, TypeScript 7.0.2, Vitest 4.1.10, markdown-it 14.1.0, KaTeX 0.18.1, Mermaid 11.16.0, DOMPurify 3.4.12, Paged.js 0.4.3, Playwright 1.54.2, Tauri 2.11.x, Rust stable 1.88.0, Docker Compose, Ubuntu 24.04 release builder.

## Global Constraints

- Run every Node, pnpm, Vite, formatter, lint, unit-test, and browser-test command through `./dev`. Do not install or invoke host Node.js or pnpm.
- Assign each coding and testing task to a single implementer. After two substantive unsuccessful attempts on the same task, hand the evidence and the current worktree to a second implementer rather than continuing. Final review is done by someone who did not write the code.
- Begin each task from a clean or intentionally documented worktree. Do not mix unrelated legacy cleanup into proof commits.
- The old StackEdit source remains reference material. Replacing the root `package.json` and retiring `package-lock.json` are intentional clean-start changes; the legacy `Dockerfile` is left untouched and must never be selected by the modern Compose configuration.
- Bind development ports only to `127.0.0.1`. Product proof must work with application network access disabled after dependencies and images are present.
- Mermaid code runs in a sandboxed, opaque-origin iframe with no Tauri capabilities. Only separately sanitized SVG crosses into preview or print output.
- Preview HTML, Mermaid SVG, and print content use distinct sanitization/capability boundaries.
- Keep Stage 0 code narrow. Do not add IndexedDB, CodeMirror, Pinia, PWA caching, history, recovery, provider integration, or full Print Studio controls here.
- Commit the exact pnpm and Cargo lockfiles generated by the pinned toolchains.
- Follow the repository instruction to prefix interactive shell invocations with `rtk`. Shell blocks below describe the underlying command sequence; execute them through `rtk` without changing application scripts.
- After each task, run the listed fresh verification command before committing.

- [ ] **Step 2: Implement the command dispatcher**

Implement `dev` as a POSIX shell script with explicit commands and no `eval`:

```sh
#!/bin/sh
set -eu

command_name=${1:-help}
pnpm_bin=${PNPM_BIN:-pnpm}
HOST_UID=${HOST_UID:-$(id -u)}
HOST_GID=${HOST_GID:-$(id -g)}
export HOST_UID HOST_GID

run_pnpm() {
  if [ "${STACKEDIT_IN_BUILDER:-0}" = "1" ]; then
    exec "$pnpm_bin" "$@"
  fi
  exec docker compose run --rm js pnpm "$@"
}

case "$command_name" in
  frontend-dev) exec docker compose up frontend ;;
  frontend-build) run_pnpm build ;;
  unit) run_pnpm unit ;;
  e2e) run_pnpm e2e ;;
  lint) run_pnpm lint ;;
  install) run_pnpm install --frozen-lockfile ;;
  install-update) run_pnpm install ;;
  shell) exec docker compose run --rm js bash ;;
  versions) run_pnpm versions ;;
  *) printf '%s\n' 'usage: ./dev {frontend-dev|frontend-build|unit|e2e|lint|install|install-update|shell|versions}' >&2; exit 64 ;;
esac
```

Make it executable. Keep `desktop-build` out until Task 7 adds the release builder.

- [ ] **Step 2: Implement a distinct SVG sanitizer**

Use DOMPurify with `USE_PROFILES: { svg: true, svgFilters: true }`, explicit forbidden tags/attributes, and a post-pass that rejects external or non-fragment URL-bearing attributes. Add `role="img"`, a responsive width, and preserve or synthesize `viewBox`. Never reuse the HTML sanitizer configuration.

- [ ] **Step 3: Build the renderer as a trusted IIFE**

`renderer-entry.ts` initializes Mermaid once with:

```ts
mermaid.initialize({
  startOnLoad: false,
  securityLevel: 'strict',
  htmlLabels: false,
  deterministicIds: true,
})
```

It accepts only versioned `postMessage` requests containing an ID, source, and theme, calls `mermaid.render`, and returns an SVG string or a serializable error. It imports no Tauri module. `vite.mermaid.config.ts` builds it as one IIFE at `apps/web/public/generated/mermaid-renderer.iife.js` before web dev or build.

- [ ] **Step 4: Host the IIFE in an opaque-origin sandbox**

`MermaidSandbox` fetches the trusted generated IIFE, embeds it into `srcdoc`, and creates an iframe with exactly `sandbox="allow-scripts"`. The `srcdoc` CSP is:

```html
default-src 'none'; script-src 'unsafe-inline'; img-src data:; style-src 'unsafe-inline';
font-src data:; connect-src 'none'; media-src 'none'; object-src 'none'; frame-src 'none'
```

The parent validates `event.source`, response schema, request ID, and timeout. It sanitizes the returned SVG before insertion. The iframe has no `allow-same-origin`, navigation, popup, download, form, or top-navigation permission.

- [ ] **Step 5: Add real-browser isolation tests**

The Playwright test renders benign and malicious diagrams and asserts:

- the renderer frame has opaque origin;
- no request leaves the Vite loopback origin;
- no dialog, navigation, popup, or global sentinel mutation occurs;
- final SVG contains no scripts, handlers, `foreignObject`, or external URL;
- malformed Mermaid produces a local placeholder while the editor remains usable.

Build `docker/browser-test.Dockerfile` from `mcr.microsoft.com/playwright:v1.54.2-noble`, copy the Node 24.18.0 runtime from a pinned Node stage, and activate pnpm 11.20.0. Add a `browser` Compose service with the same source mount and dependency volumes but no published port. Change `./dev e2e` to run `docker compose run --rm browser pnpm e2e`, and extend the wrapper contract test to assert this exact dispatch.
